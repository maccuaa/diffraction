# Load jsdiff via a cdnjs UMD `<script>` tag plus a local ES module shim

The `diff` import map entry had no integrity protection: unlike the Pico CSS `<link>`, which carries a Subresource Integrity hash, no ESM build of jsdiff on a static CDN could be SRI-pinned via the browser's newer (2026-era) import-map `integrity` key without depending on a very recent browser feature. cdnjs — already used for Pico CSS, with Renovate's built-in `html` manager auto-updating both version and SRI hash together — hosts jsdiff, but only as a UMD bundle (`window.Diff = {...}`), not an ES module, so it can't directly back the `"diff"` import map entry (confirmed in ADR 0003).

Instead, `index.html` now loads jsdiff from cdnjs via a plain SRI-pinned `<script>` tag (a classic, non-module script, so it runs and sets `window.Diff` before any deferred module script executes). The import map's `"diff"` entry now points at a tiny first-party file, `src/vendor/diff-shim.js`, which re-exports `window.Diff`'s named functions as ES module exports. This keeps `src/diff-logic.js`'s `import { diffArrays, diffChars } from 'diff'` unchanged — it still resolves to the real npm `diff` package under Node (`node --test`, via `package.json`'s devDependency) and, in the browser, to the shim backed by the UMD global. No environment-detection branching was added to `diff-logic.js`, so it stays the project's one pure, unit-tested module.

## Consequences

Renovate's built-in `html` manager (not a custom regex manager) now tracks the cdnjs `<script>` tag directly, updating its version and SRI hash together in one automerge-safe step, the same as Pico CSS — so the custom regex manager and the `automerge: false` override from the previous draft of this decision are no longer needed. A `packageRules` entry groups the npm `diff` devDependency with the cdnjs `jsdiff` dependency so both bump together in one PR. The tradeoff is one more file (`src/vendor/diff-shim.js`) and a load-order dependency (the classic `<script>` tag must appear before the import map / module scripts in `index.html`) that isn't enforced by tooling — only by comment and code review.
